# 식당 메뉴 영양성분 추정 프로토콜 결정안

상태: 이미지 입력 검증 전 잠정안  
기준일: 2026-10-18

## 결론

공식 영양정보 4,000개를 검색 기준 데이터로 사용하고, 기존 브랜드와 처음 보는
브랜드를 분리해 처리한다. 기존 브랜드는 하이브리드 RAG를 사용한다. 미관측
브랜드는 RAG를 먼저 실행해 confidence가 0.7 이상이면 채택하고, 그보다 낮으면
순수 LLM으로 재추정한다. 최종 confidence가 0.6 미만이면 값을 제공하지 않는다.

## 처리 흐름

1. 메뉴명·브랜드·식당 카테고리·메뉴 카테고리·중량을 검증한다.
2. 브랜드가 공식 영양정보 데이터에 존재하는지 판별한다.
3. 문자 bigram 45%, Gemini 임베딩 55%, 식당 카테고리 +0.08, 메뉴 카테고리
   +0.12로 후보 점수를 계산한다.
4. 공식 영양정보가 있는 상위 8개 메뉴를 RAG 근거로 사용한다.
5. 기존 브랜드는 RAG 결과를 사용한다.
6. 미관측 브랜드는 RAG confidence가 0.7 이상이면 채택하고, 미만이면 근거 없는
   순수 LLM을 한 번 더 호출한다.
7. 최종 confidence가 0.6 미만이거나 숫자 유효성 검사를 통과하지 못하면 보류한다.
8. 숫자 형식 실패는 한 번만 재시도한다.

## 근거

| 대상 | 방식 | 열량 MAE | ±30% | 커버리지 |
|---|---|---:|---:|---:|
| 기존 브랜드 | 하이브리드 RAG | 48.72kcal | 82.5% | 100% |
| 미관측 브랜드 | 순수 LLM | 126.43kcal | 48.5% | 100% |
| 미관측 브랜드 독립 평가 | confidence 분기 | 112.22kcal | 53.4% | 100% |
| 미관측 브랜드 독립 평가 | 분기 + 0.6 미만 보류 | 103.48kcal | 53.8% | 89.7% |

미관측 브랜드 RAG confidence가 0.7 이상인 비율은 현재 표본에서 44%다. 따라서
미관측 브랜드의 약 56%는 RAG 호출 후 순수 LLM 호출이 추가될 수 있다.

## 데이터 규모

- 기존 브랜드는 4,000개까지 정확도 개선이 확인됐다.
- 미관측 브랜드의 단순 문자·임베딩 검색은 1,000개 이후 개선이 정체됐다.
- 현재 운영 기준 데이터는 4,000개가 적절하다.
- 6,716개 전체를 모두 프롬프트에 넣지 않고 검색 후보 8개만 전달하므로 데이터가
  늘어도 LLM 요청 시간이 선형 증가하지 않는다.

## 호출·성능

- 실시간 요청: Standard 단건 호출
- 대량 보강: 공식 Batch API 우선, 즉시 처리가 필요하면 10개 묶음
