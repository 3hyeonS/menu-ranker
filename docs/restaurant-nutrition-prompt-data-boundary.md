# 영양 추정 프롬프트 데이터 경계

## 외부 전송 허용

- 목표 메뉴 ID(내부 벤치마크·요청 상관관계용 임의 ID)
- 메뉴명, 브랜드
- 식당 카테고리, 메뉴 카테고리
- 메뉴 중량
- RAG 근거 메뉴의 위 항목과 공식 영양성분

## 외부 전송 금지

- 사용자 ID, 이메일, 전화번호, 주소, 생년월일
- 식사·운동·체중·월경 기록
- 사용자 목표, 질환, 알레르기 등 프로필
- 목표 메뉴의 정답 영양성분
- API 키와 내부 인증 정보

영양 추정은 메뉴 자체의 속성만으로 수행하므로 사용자 데이터가 필요하지 않다.
향후 API 구현 시 restaurant 모듈의 메뉴 입력 DTO만 추정 서비스에 넘기고,
`UserEntity`, `MealEntity`, `ChatHistoryEntity`를 의존성으로 주입하지 않는다.

자동 점검:

```bash
npm run restaurant:nutrition-prompt:audit
```

이 점검은 목표 영양 정답에 고유한 sentinel 값을 넣어 프롬프트에 노출되지 않는지,
사용자 관련 금지 키가 없는지, RAG일 때만 근거 영양정보가 포함되는지 확인한다.
