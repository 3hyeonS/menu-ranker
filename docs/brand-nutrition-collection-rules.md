# 브랜드 메뉴·영양정보 수집 규칙

최종 갱신: 2026-10-25 (이슈 #3에서 처음부터 다시 수집하기로 하고 전면 개정, 롯데리아 테스트 수집 결정 반영)

브랜드 메뉴·영양정보를 수집·수정·재출력하는 모든 요청마다 **작업 시작 전에 이 문서 전체를 읽고** 따른다. 세션·터미널이 달라도 이 문서가 기준이다. 사용자의 새 지시가 이 문서보다 우선한다.

- 수집·수정 요청이 끝나면 이 문서에 추가할 만한 내용을 정리해 사용자에게 보여 주고, 허락을 받은 뒤 갱신한다.
- 이 문서의 기준에 해당하지 않는데 판단이 모호한 경우는 모두 처리 필요로 분리한다.

## 1. 데이터 폴더

수집 결과는 **메인 체크아웃**(`/home/sehyeon/menu-ranker`)의 `brand-nutrition/`에 둔다. 이 폴더는 `.gitignore` 대상이며 커밋하지 않는다. 이슈별 worktree 안에 두면 머지 후 worktree를 정리할 때 함께 지워지므로, worktree 세션에서도 메인 체크아웃 경로에 쓴다.

```text
brand-nutrition/
  template.csv                  # 표준 23열 헤더만
  all-menus.csv                 # 전체 데이터: 모든 브랜드의 정상 행
  brand-info.csv                # 브랜드별 정보 (4절)
  legacy/                       # 2026-10-25 이전 데이터(참고용, 수정하지 않음)
  brands/<공식 한글 브랜드명>/
    normal.csv                  # 정상 메뉴
    needs-review.csv            # 처리 필요 메뉴
```

- 모든 CSV는 Excel에서 바로 열리도록 **UTF-8(BOM) + CRLF**로 저장한다.
- 브랜드 폴더 이름은 공식 한글 브랜드명을 쓴다(예: `brands/파리바게뜨/`).
- 작업 순서: 브랜드를 수집해 정상·처리 필요로 분류 → `brands/<브랜드>/`에 두 파일 저장 → `all-menus.csv`에서 그 브랜드의 기존 행을 지우고 새 정상 행을 추가 → `brand-info.csv` 갱신.
- 처리 필요 행이 없어도 헤더만 있는 `needs-review.csv`를 만든다.
- `legacy/`의 이전 데이터는 시작점으로 쓰지 않는다. 빈 전체 데이터에서 다시 수집한다.
- 수집 중 내려받은 원본·캐시 같은 임시 파일은 세션 scratchpad나 `/tmp`에 두고 데이터 폴더에 남기지 않는다.

## 2. 표준 열

정상 파일과 `all-menus.csv`, `template.csv`는 다음 23열의 이름과 순서를 그대로 쓴다.

```text
메뉴,브랜드,브랜드 카테고리,메뉴 카테고리,중량 단위,중량,총중량,단위량,칼로리,탄수화물,당류,당알코올,식이섬유,단백질,지방,포화지방,트랜스지방,불포화지방,나트륨,카페인,칼륨,콜레스테롤,알코올
```

- 처리 필요 파일은 23열 뒤에 `처리 유형`, `처리 사유` 두 열만 추가한다. 다른 보조 열은 만들지 않는다.
- `처리 사유`는 무엇이 문제인지와 원문 값을 구체적으로 적는다. 사유가 여럿이면 모두 적고, 해결된 사유만 지운다. 모든 사유가 해결되면 정상으로 옮긴다.
- `scripts/import-restaurant-menus.ts`는 이 23열을 읽는다. `총중량`은 형식만 검증하고 DB에는 저장하지 않는다.

## 3. 수집 범위와 출처

- **공식 홈페이지에 게시된 정보만** 사용한다. 수집 요청과 함께 받은 링크·자료가 있으면 그것을 우선한다.
- 사용자는 브랜드마다 링크나 사진을 함께 준다.
  - 사진: 영양성분표 사진이다. 사진의 값을 그대로 옮기고, 읽을 수 없는 값은 추정하지 않고 처리 필요로 분리한다.
  - 영양성분표 링크: 그 표를 기준으로 수집한다.
  - 메뉴 페이지 링크: 브랜드가 영양성분표를 따로 공시하지 않고 메뉴를 하나씩 눌러야 영양성분이 나오는 경우다. **모든 메뉴 카테고리와 하위 카테고리(탭·필터·더보기·페이지 넘김 포함)를 빠짐없이 확인**하고, 각 메뉴의 상세 페이지·팝업에서 영양성분을 모두 확인한다. 수집 후 카테고리별 메뉴 수를 홈페이지 목록과 대조해 누락이 없는지 확인한다.
  - 일부 브랜드는 메뉴 페이지의 `영양성분` 버튼·칸을 누르면 전체 영양성분표로 이어진다. 이런 표가 있으면 그 표를 영양성분표로 보고 3절의 영양성분표 우선 규칙을 적용한다.
- 요청 범위의 모든 하위 카테고리·개별 상세 페이지·공식 사이즈·온도·도우·옵션을 확인한다. 같은 제품이 여러 목록에 노출되면 한 번만 수집한다.
- 사이즈·온도·도우·엣지·토핑·옵션이 다르면 별도 메뉴다. 이름 일부나 카테고리가 같다고 다른 제품을 합치지 않는다.
- 영양성분표와 각 메뉴 상세보기 정보가 다르면 **영양성분표 값**을 쓴다.
- 원문의 명백한 메뉴명 오타는 고친다(예: `말차라뗴` → `말차라떼`). 고친 내용은 `brand-info.csv` 비고에 원문과 함께 적는다. 영양값의 오기로 보이는 값은 고치지 않고 7절대로 처리 필요로 분리한다.

## 4. 브랜드별 정보 (`brand-info.csv`)

브랜드 하나당 한 행. 열: `브랜드,브랜드 카테고리,공식 출처 URL,영양성분 공시일,수집일,뼈 포함 여부,정상 행 수,처리 필요 행 수,비고`

- 공식 출처 URL이 여럿이면 ` | `로 구분한다.
- 영양성분 공시일: 홈페이지·영양성분표에 적힌 공시일·게시일·개정일·기준일을 원문 그대로 적는다. 찾지 못하면 `공시일 확인 불가`로 적는다. 이미지 파일 경로의 날짜로 추정하지 않는다.
- 수집일: 실제 수집한 날짜(YYYY-MM-DD).
- 뼈 포함 여부: 치킨 등 뼈 있는 메뉴가 있는 브랜드만 `뼈 포함` / `뼈 제외` / `공시 없음` 중 하나를 적는다. 메뉴마다 다르면 `메뉴별 상이`로 적고 비고에 구분을 적는다. 해당 없는 브랜드는 공란.
- 비고: 영양 기준(예: 100g당, 1회 제공량 기준), 컵 용량 표, 브랜드가 공시한 주의 문구, 수집 시 내린 판단 등 참고할 만한 내용.
- 행 수는 해당 브랜드의 `normal.csv`, `needs-review.csv` 데이터 행 수와 일치해야 한다.

## 5. 중량·총중량·단위량

- **`중량`은 제품 총중량이 아니라 영양성분의 기준 중량**이다.
- `중량 단위`는 숫자로 저장한다: g=`0`, ml=`1`. 숫자 `0`은 유효한 g 코드다. g↔ml 변환은 하지 않는다.
- 총중량이 따로 있고 영양 기준 중량과 다르면, 총중량은 `총중량` 열에 숫자로, 기준 중량은 `중량` 열에 숫자로, `단위량` 열에는 기준 중량을 문자로 적는다(예: 중량 `100`, 총중량 `250`, 단위량 `100g`).
- 영양 기준 중량이 총중량보다 크면 처리 필요로 분리한다.
- 중량이 0이거나 없으면 처리 필요로 분리한다.
- 중량과 영양성분은 같은 기준을 써야 한다. 일부 성분만 기준이 다르면 처리 필요로 분리한다(예: 중량 50g, 탄수화물 10g, 단백질(100g당) 5g).

### 단위량

1. 단위량이 적혀 있거나 별도로 공시된 단위량이 있으면 그것을 쓴다(우선 적용).
2. 총중량이 기준 중량과 다르면 위 규칙대로 기준 중량을 문자로 적는다.
3. 음료는 단위량을 `1잔`으로 쓴다. 단, 500ml·1.25L 등 병·페트 음료는 `1병`, 캔은 `1캔`으로 쓴다.
4. 위에 해당하지 않는 먹는 메뉴는 메뉴명에 개수가 있으면 그 개수를 쓰고(예: `화이어윙2조각` → `2조각`), 없으면 기준 중량을 문자로 쓴다(예: 중량 263g → `263g`). 공시되지 않은 `1개` 같은 개수는 쓰지 않는다.
- 빙수·아이스크림·케이크 등 먹는 메뉴는 컵에 담겼거나 음료 카테고리에 있어도 `1잔`으로 쓰지 않는다.
- 조각 수·인분 수·한 판 중량 같은 값을 유추하지 않는다.

### 음료 컵 용량 oz 환산 (모든 브랜드 공통)

| oz | 저장값 |
| --- | --- |
| 12oz | 355 (ml, 단위 코드 1) |
| 16oz | 473 |
| 22oz | 650 |

- 브랜드가 공식 g·ml 제공량을 따로 밝혔으면 그 값을 우선한다. 영양값은 재계산하지 않는다.
- 14oz·32oz 등 표에 없는 크기는 환산하지 않고 처리 필요로 분리하며 원문 oz를 사유에 남긴다.
- `12oz/16oz`처럼 여러 크기가 함께 적혀 메뉴별 대응이 불명확하면 하나를 고르지 않고 처리 필요로 분리한다.

## 6. 영양값 기록

- 공식 값만 기록한다. 미공개 값을 추정하거나 0으로 채우지 않는다. 공식 숫자 0은 그대로 둔다.
- `-`와 공란은 빈 값으로 둔다. **일부 성분만 미공개인 메뉴는 정상**으로 처리한다.
- 값에서 단위·특수문자를 없애고 숫자만 남긴다(`1,234mg` → `1234`). 소수점은 유지한다.
- **`~g 미만`, `~ 이하`(`<`, `≤`, `<=` 포함)는 해당 숫자의 음수**로 기록한다(예: `1g 미만` → `-1`). 이것만 있는 행은 정상이다. `0 미만`·`0 이하`는 음수로 표현할 수 없으므로 처리 필요로 분리한다. `이상`·`초과`는 음수로 바꾸지 않고 처리 필요로 분리한다.
- 범위값은 `000~000` 원문 형태로 저장하고 **처리 필요**로 분리한다(예: `120~150`). 세트·콤보·팩처럼 구성에 따라 열량 범위만 공시된 메뉴도 수집해 처리 필요로 둔다.
- 위 경우 외에 값이 단일 숫자가 아니면 처리 필요로 분리하고 원문을 해당 열에 남긴다(예: 카페인 `커피분말 5%`).
- 단위 오기가 의심되면 임의로 환산하지 않고 처리 필요로 분리한다(예: 콜레스테롤이 mg이 아니라 g으로 표기).

## 7. 영양성분 이상치 검사

모든 행을 저장하기 전에 전체적으로 검사하고, 이상한 메뉴는 처리 필요로 분리해 사유를 구체적으로 적는다. 정해진 수치 기준은 두지 않고 수집하는 쪽에서 판단하되, 최소한 다음을 확인한다.

- 탄수화물·단백질·지방 등 성분 값이 기준 중량을 넘는 경우
- 당류가 탄수화물보다 크거나, 포화·트랜스지방이 지방보다 큰 경우처럼 포함 관계가 맞지 않는 경우
- 탄수화물·단백질·지방으로 계산한 열량이 공시 열량과 크게 다른 경우
- 0kcal일 가능성이 낮은데 0kcal인 경우
- 같은 제품의 다른 사이즈·도우·옵션과 비교해 혼자 크게 튀는 값(예: 바질 마스카포네 L Thin/오리지널의 단백질 63g)
- 같은 성분이 두 번 적힌 경우(예: `탄수화물 10g, 단백질 20g, 지방 5g, 단백질 12g`)
- 원본 표의 구조가 어긋난 경우. 파싱 결과만 이상하면 실제 화면과 표 배치를 다시 확인하고, 화면이 정상인 행을 파싱 오류 때문에 처리 필요로 보내지 않는다.

이상치로 분류해도 공식 값을 계산으로 보정하지 않는다.

## 8. 중복 메뉴

- 메뉴명·카테고리·사이즈·토핑·옵션 등 하나의 메뉴로 특정할 수 있는 특성이 모두 같아야 중복이다.
- 같은 메뉴명에 영양값도 같으면 **하나만 정상에 남기고 나머지는 버린다**(처리 필요에 넣지 않는다).
- 메뉴명에서 수량만 다르고 중량·영양값이 같으면 하나만 정상에 남기고 나머지는 버린다.
- 보냉백·포장 등 음식이 아닌 옵션만 다르고 중량·영양값이 같으면 옵션을 메뉴명에서 빼고 한 행으로 합친다(예: `말차빙수(보냉백 포함)`·`말차빙수(보냉백 미포함)` → `말차빙수`).
- 같은 메뉴명인데 영양값이 다르면 해당 행 모두 처리 필요로 분리한다(값 충돌).
- 브랜드 파일 사이, `all-menus.csv` 안에서도 중복이 없는지 확인한다.

## 9. 제외

- 중량·열량·영양성분이 모두 없는 메뉴는 두 파일 모두에서 뺀다.
- 브랜드별 수집 제외 대상은 10절을 따른다.

## 10. 브랜드별 규칙

- **파리바게뜨**: 총중량만 있고 영양성분 기준 중량을 알 수 없으면 처리 필요로 분리한다.
- **피자헛**: `핫소스만 빼주세요`, `핫소스, 피클 모두 빼주세요` 같은 옵션 항목은 수집하지 않는다.
- **매머드커피**: 공식 컵 크기는 HOT S 12oz / M 16oz / L 22oz, ICE S 14oz / M 22oz / L 32oz다. 5절 환산표를 적용하고, 14oz·32oz는 처리 필요로 분리한다.
- **투썸플레이스**: 공식 표 하단 음료 용량 HOT R 355ml / L 473ml, ICE R 414ml / L 473ml / M 591ml을 쓴다. 온도 표시가 없는 음료는 ICE 용량을 쓴다. S·D·ONE SIZE 메뉴는 표에 용량이 없으므로 개별 메뉴 페이지에서 확인하고, 확인되지 않으면 처리 필요로 분리한다.

2026-10-22 이전 규칙에 있던 다른 브랜드별 예외(메가MGC커피, 달콤커피, 탐앤탐스, 텐퍼센트커피, 팔공티, 폴바셋, 피자마루, 고피자 등)는 폐기했다. 해당 브랜드를 수집할 때 사용자에게 다시 확인하고 이 절에 추가한다.

## 11. 저장 전후 검증

1. 파일을 다시 읽어 BOM, 헤더(23열/25열) 이름·순서, 행 수를 확인한다.
2. `중량 단위`는 `0`·`1`만 있는지 확인하고, 정상 파일의 `중량`이 0·공란이 아닌지 확인한다.
3. 정상 파일의 숫자 열에 숫자가 아닌 값(범위값·단위 문자열 등)이 없는지 확인한다.
4. ‘미만·이하’ 원문이 모두 음수로 저장됐는지, 원래 0·공란이 바뀌지 않았는지 확인한다.
5. 브랜드 파일 안, 정상·처리 필요 파일 사이, `all-menus.csv` 안에 중복·누락이 없는지 확인한다.
6. `all-menus.csv`의 해당 브랜드 행이 `normal.csv`와 일치하는지 확인한다.
7. `brand-info.csv`의 행 수가 실제 파일과 일치하는지 확인한다.
8. 음료의 단위량이 `1잔`(병·캔은 `1병`·`1캔`)인지 확인한다.
9. 실행한 검증과 남은 처리 필요 항목을 보고한다.

## 12. 하지 않는 것

- DB 변경·`restaurant:import`(restaurant 테이블 전체 삭제 후 재삽입)·벡터 인덱싱·마이그레이션은 사용자의 별도 명시적 요청 없이 실행하지 않는다.
- 현재 import 스크립트는 음수 값과 범위값을 거부한다. ‘미만’ 음수 값은 import 스크립트를 수정해 처리하기로 했다(2026-10-25 결정, 처리 방식은 별도 작업에서 정한다). 수집 파일에는 이 문서대로 음수를 기록한다.
