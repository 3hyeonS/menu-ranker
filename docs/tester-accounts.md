# 테스트 계정 권한 분류

사용자 권한(`user.authorityRole`)은 `USER`, `TESTER`, `ADMIN`으로 구분합니다.
내부 테스트 계정은 실제 DB 권한을 `TESTER`로 지정하며,
로그인·토큰 갱신 응답의 `user.role` 및 프로필 응답의 `role`에 그대로 반환됩니다.
별도 `is_tester` 필드나 환경변수는 사용하지 않습니다.

- `TESTER`는 일반 사용자용 권한 검사에 통과하지만 관리자 권한은 갖지 않습니다.
- 신규 JWT는 `role: TESTER`로 발급되며 인증 단계에서 이를 허용합니다.
- 기존 USER 토큰도 DB의 현재 권한을 조회하므로 변경된 프로필을 가져올 수 있습니다.
- 테스터 지정은 구독 상태와 독립적입니다. 구독이나 구독 코드를 발급하지 않습니다.
- ID 6, 113을 테스트 계정으로 지정하며 기존 미구독 상태를 유지합니다.

현재 권한 열은 MySQL `varchar`이고 `authority.role`을 참조합니다.
`authority`에 `TESTER` 행을 추가하고 대상 계정의 `authorityRole`을 변경하는 데이터
작업만 필요합니다. DB 스키마 변경이나 TypeORM 마이그레이션은 필요하지 않습니다.
추가 테스터 지정 시에도 같은 방식으로 계정별 권한만 변경합니다.

## 앱과 Amplitude

앱은 로그인 또는 프로필 응답을 다시 조회해 `role: TESTER`를 반영해야 합니다.
프런트에 USER/ADMIN만 허용하는 분기나 열거형이 있다면 TESTER를 일반 사용자로
처리하도록 함께 갱신해야 합니다.

백엔드는 Amplitude 사용자 속성을 직접 전송하지 않습니다.
앱에서 `role`을 Amplitude 사용자 속성에 반영하고 분석에서 `role != TESTER` 조건을
적용해야 테스트 활동을 제외할 수 있습니다. 과거 이벤트 제외 범위는 분석 설정에서
별도로 확인합니다.
