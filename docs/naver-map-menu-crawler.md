# 네이버 지도 송파구 식당 메뉴 수집

이슈 #26. 네이버 지도(플레이스)에서 서울 송파구 식당의 메뉴명·가격·메뉴 사진 URL을 모아 CSV 하나로 저장한다.

- **내부 분석 전용**이다. 앱 화면 노출·운영 DB 적재를 하지 않는다. 사진은 URL만 저장하고 이미지 파일은 내려받지 않는다.
- 네이버 지도 크롤링은 이용약관·DB제작자권 위험이 있다. 사용자가 이를 인지하고 진행하기로 결정했다(2026-10-28).
- 실제 네이버에 요청하는 실행은 외부 호출이므로 사용자 허락을 받은 뒤에만 한다.

## 동작

1. **식당 목록 수집**: `서울 송파구 <행정동> <키워드>`로 `pcmap.place.naver.com/restaurant/list`를 검색해 place_id를 모은다. 검색 결과 상한 때문에 행정동 27개 × 업종 키워드로 잘게 나누고, 쪽마다 새 식당이 없으면 다음 검색으로 넘어간다. 주소에 `송파구`가 없는 식당은 버린다. 목록에 주소가 비어 있으면 일단 남기고 메뉴 페이지 주소로 다시 거른다. 앞 검색에서 찾은 식당만 나온 쪽이어도 다음 쪽은 계속 보고, 결과가 없거나 앞 쪽과 같은 결과만 오면 멈춘다.
2. **메뉴 수집**: place_id마다 `pcmap.place.naver.com/restaurant/<id>/menu/list`를 열어 메뉴명·가격·첫 번째 사진 URL을 뽑는다.

두 페이지 모두 HTML 안의 `window.__APOLLO_STATE__` JSON(Apollo 캐시)을 파싱한다. 식당 요약은 `...ListSummary` 타입, 메뉴는 `...Menu` 타입, 메뉴 페이지의 식당 정보는 `PlaceDetailBase:<id>`에서 읽는다.

## 실행

```sh
# 시험 실행: 한 개 동, 키워드 하나, 식당 10곳만
npm run naver-map:crawl-songpa -- --out=<출력.csv> --dongs=잠실본동 --keywords=음식점 --max-places=10

# 전체 실행 (메인 체크아웃에서)
npm run naver-map:crawl-songpa -- --out=naver-map/songpa-menus.csv
```

- 출력 경로는 반드시 인자로 받는다. git 저장소 안이면 `.gitignore` 대상이어야 하고, 아니면 실행을 거부한다. 저장소 루트의 `/naver-map/`이 ignore 대상이다.
- worktree 안에 두면 머지 후 worktree를 정리할 때 함께 지워지므로, 전체 실행 결과는 메인 체크아웃(`/home/sehyeon/menu-ranker/naver-map/`)에 둔다.

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--out=` | (필수) | 결과 CSV 경로 |
| `--dongs=` | 송파구 행정동 27개 | 쉼표 구분. 예: `잠실본동,잠실2동` |
| `--keywords=` | 음식점, 한식, 중식, 일식, 양식, 아시아음식, 분식, 치킨, 피자, 패스트푸드, 고기, 해산물 | 쉼표 구분. 카페·디저트·술집은 기본 제외(포함 여부 미정) |
| `--district=` | `송파구` | 주소 필터. 빈 값이면 거르지 않음 |
| `--max-pages=` | 5 | 검색 하나당 최대 쪽 수 |
| `--page-size=` | 50 | 쪽당 결과 수(`display`) |
| `--min-delay-ms=` / `--max-delay-ms=` | 1000 / 3000 | 요청마다 이 범위에서 무작위로 쉰다 |
| `--concurrency=` | 1 | 동시 요청 수(최대 2) |
| `--max-retries=` | 3 | 403·429·5xx·네트워크 오류·차단 페이지 재시도 횟수 |
| `--backoff-ms=` | 10000 | 재시도 대기 시작값. 시도마다 2배 + 지터 |
| `--max-consecutive-blocks=` | 3 | 재시도를 소진한 요청이 연속 이만큼이면 전체 실행을 멈춘다 |
| `--max-places=` | 0(무제한) | 이번 실행에서 메뉴를 수집할 식당 수 |
| `--discover-only` | - | 식당 목록만 모으고 메뉴는 수집하지 않음 |
| `--timeout-ms=` | 15000 | 요청 하나의 타임아웃 |

## 결과 파일과 재시작

출력 CSV(`<out>`)와 같은 폴더에 진행 상태 파일이 생긴다.

| 파일 | 내용 |
|---|---|
| `<out>` | `place_id, 식당명, 주소, 카테고리, 메뉴명, 가격, 사진URL`. 메뉴 1개당 1행, 메뉴가 없는 식당은 메뉴 칸을 비운 1행. UTF-8(BOM) + CRLF |
| `<out>.queries.txt` | 끝난 검색(검색어·쪽 수·쪽 크기·지역 필터). 옵션을 바꾸면 새 검색으로 본다 |
| `<out>.places.jsonl` | 발견한 식당(place_id 중복 제거 전 원본, 읽을 때 첫 값을 씀) |
| `<out>.failed.jsonl` | 메뉴 수집에 실패한 식당과 이유(기록용) |
| `<out>.excluded.txt` | 메뉴 페이지 주소로 지역 밖이라 제외한 place_id(다시 수집하지 않음) |

- 중단(Ctrl+C, 차단으로 멈춤 등)된 뒤 **같은 명령을 다시 실행**하면 이어서 한다. 끝난 검색은 다시 하지 않고, CSV에 행이 있는 place_id는 건너뛴다. 실패한 식당은 CSV에 없으므로 다음 실행에서 자동으로 재시도한다.
- 식당 하나의 행은 한 번의 쓰기로 덧붙인다. 중단으로 CSV 마지막 줄이 덜 쓰였으면(`\r\n`으로 끝나지 않으면) 다음 실행 시작 때 그 줄을 지운다. `places.jsonl`의 깨진 줄은 무시한다.
- 숫자 옵션은 정수만 받는다. `--concurrency`는 1~2, `--max-pages`·`--page-size`·`--max-consecutive-blocks`는 1 이상.
- 저장소 안 출력 경로의 git ignore 여부를 확인하지 못하면(git 없음 등) 실행을 거부한다.
- 처음부터 다시 하려면 `<out>`과 `<out>.*` 파일을 지운다.
- 가격은 페이지 표기 그대로(`3,500`, `변동` 등) 저장한다. 사진이 여러 장이면 첫 장만 저장한다. 값 안의 줄바꿈은 공백으로 바꾼다.

## 테스트

```sh
npm test -- --runInBand scripts/naver-map
```

`scripts/naver-map/__fixtures__/`의 HTML 픽스처와 Fake fetcher로 파싱, CSV 출력, 지역 필터, 재시작, 백오프, 연속 차단 시 중단을 검증한다. 네트워크를 쓰지 않는다. 픽스처는 알려진 페이지 구조를 따라 만든 가상 데이터이므로, 실제 응답 구조가 다르면 시험 실행 결과로 픽스처와 파서를 함께 고친다.
