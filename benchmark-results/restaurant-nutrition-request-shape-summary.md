# LLM 영양 추정 단건·배치 호출 비교

- 모델: `gemini-2.5-flash-lite`
- 단건 실험: 분할·방식별 20개, 총 80회 호출
- 배치 실험: 10개씩 묶어 호출

## 처리 성능

| 호출 형태 | 메뉴당 총 토큰 | 메뉴당 평균 처리시간 | 사용자 관점 p95 | 실패율 |
|---|---:|---:|---:|---:|
| 단건 | 약 582 | 약 831ms | 0.92~1.04초 | 0% |
| 10개 배치 | 약 401 | 약 213ms | 배치 전체 1.88~2.78초 | 출력 유효성 2.5% |

단건은 메뉴당 토큰이 배치보다 약 45% 많고 처리량이 낮다. 반면 한 메뉴를 바로
응답해야 하는 API에서는 전체 응답시간이 약 1초라 배치 대기보다 유리하다.

## 동일 20개 표본 열량 MAE

| 분할·방식 | 단건 | 10개 배치 |
|---|---:|---:|
| 기존 브랜드 순수 LLM | 84.92kcal | 92.63kcal |
| 기존 브랜드 RAG | 55.27kcal | 55.75kcal |
| 미관측 브랜드 순수 LLM | 110.38kcal | 103.73kcal |
| 미관측 브랜드 RAG | 129.61kcal | 121.33kcal |

표본이 작고 생성 모델의 변동성이 있으므로 정확도 차이는 호출 형태의 우열로
해석하지 않는다.

## 권장

- 사용자가 한 메뉴를 요청하는 실시간 API는 단건 호출을 사용한다.
- 네이버 수집 메뉴를 대량 보강하는 비동기 작업은 10개 배치를 사용한다.
- 배치 응답은 항목 수와 숫자 유효성을 검사하고, 누락된 항목만 단건 재시도한다.
